## Answered today, do not re-litigate

- **The category delete is not broken.** I said this morning it was a confirmed bug. That was more
  than I had earned, and it was wrong. The owner's database **came out of a backup restore**, and
  a restore upserts every category straight from the archive (`categories.forEach { categoryDao.upsert(it) }` in `BackupManager`) while the
  post-restore prune only sweeps `BuiltInCategory.RETIRED_IDS`. So a category deleted before the
  archive was made comes back. The delete path is correct. `custom_android_10` is still on his bar
  because of that, and deleting it now will stick.
- **The same restore explains the half-saved ScreenScraper account.** `ss_username` is a backed-up
  string; `ss_password` is in `ENCRYPTED_CREDENTIAL_KEYS` and dropped when it cannot be decrypted
  on the receiving device. One cause, both symptoms.
- **Playtime per game already exists.** `games.total_play_time_millis`, incremented by
  `GameDao.addPlayTime`, written from `LaunchDispatcher.onHostResumed` (the only caller of `recordPlaySession`), rendered by
  Game Detail when above zero. 2 of 148 games have it, being the two launched since it landed.
  Two honest limits: it is **wall clock from dispatch to return**, not foreground time, so
  pressing home mid-game keeps counting; and it is recorded only in `onHostResumed`, so a killed
  process loses the session. `PACKAGE_USAGE_STATS` is already declared and
  `InstalledAppRepository` already uses `UsageStatsManager`, so the accurate version is
  available without new permissions.
- **IGDB works, and it is the first time it ever has.** Verified end to end after the token fix:
  `api.igdb.com/v4/games` answering 200 and covers downloading from `images.igdb.com`. A
  Scrape Missing run filled **19 of 34** games, every one from IGDB; the other 14 are titles IGDB
  does not carry, not errors. `artwork_records` stands at 1,076 afterwards. Before today IGDB had
  never returned a single asset, because its OAuth request could not authenticate at all.
- **"No artwork found" for Skyrim was a bad SteamGridDB key, not a bug.** Every SGDB call returned
  **401**, including the `/games/steam/489830` id lookup, so it was never about the query. An
  SGDB key is 32 characters and the stored one was **33** — one stray character, and `saveKey`
  already trims whitespace, so not a space. Re-entering it fixed it. Ruled out on the way, with a
  length-only probe that never logged the value: the key decrypts correctly, so this was not the
  hazard below.
- **`KeystoreSecretCipher.decryptOrLegacy` returns the stored string verbatim on ANY failure**, so
  a value that WAS sealed but can no longer be opened is handed to an API as if it were the key —
  silently, and indistinguishable from a legacy plaintext key. It was not the cause of the SGDB
  401, but it is a live trap: "not our ciphertext" and "ours and unopenable" collapse to one
  answer. `isUsableOnThisDevice` already draws that distinction and is used **only** by the
  restore path. Worth giving the read path the same knowledge. **Not done.**
- **Steam playtime is a separate thing.** `SteamStoreApi` is store-only (`appdetails` + the asset
  CDN, no key, which is why it is the cheap provider). `playtime_forever` lives on the Web API and
  needs a Web API key, a SteamID64 and a public profile.
- **"Online" → "Network" was never a code bug.** `Category.kt` has said Network for a long time;
  `reconcileBuiltInCategories` uses INSERT OR IGNORE and never writes a name. Corrected by a
  targeted one-shot, guarded on the name still being exactly "Online" — because his `games` row is
  renamed to **"Emulation"** and a blanket name sync would have reverted it.
- **Shelves was not a concept to delete.** It lists the configured root folders, and he has exactly
  one (`" Library"`, leading space, 80 books), so the row opened a list of one holding the same
  books. Hidden at ≤1 shelf, by the rule the Series row two lines above already used.
- **Music was always searchable, just invisibly.** The browser has an always-visible search field;
  what was missing was the row every other column had. Both exist now.
- **TheGamesDB has no free anonymous access**, so with no key every lookup was skipped anyway.
  Removing it cost nothing that was working.

### Traps that cost time today

- **Injected face buttons never reach NeoStation.** `input keyevent BUTTON_Y` (keyboard source)
  and `input gamepad keyevent BUTTON_Y` both did nothing. DPAD works; **touch works**; their
  footer prompts are ordinary clickable views. Before concluding a button does nothing, prove the
  channel by tapping a labelled control.
- **A ticking clock defeats an md5 "did the screen change?" check.** Two frames differ because the
  minute rolled. Compare against every prior frame, mask the status bar, or check the view tree.
- **`./gradlew … | grep …` swallows gradle's exit code.** I installed a build once while two tests
  were red because of this. Check the status, not the last line of a pipeline.
- **`minimumInteractiveComponentSize()` reserves 48 dp of LAYOUT**, not just touch area. A comment
  here claimed otherwise and was wrong; it is what made the hint pill 54 dp tall.
- **`adb shell input text` for a secret is not trustworthy.** The typed ScreenScraper/IGDB secret
  was rejected repeatedly while the same string worked from curl. Settings ▸ Artwork ▸ **Load
  Credentials File** (a `.properties` file with `steamgriddb.apiKey`, `igdb.*`, `screenscraper.*`)
  worked first time. Delete the file afterwards.
- Still true from the last session: **A launches a game** from the detail page, use Y for options;
  **two assertion libraries** with opposite message positions (`org.junit.Assert.assertEquals` puts
  the message first, `kotlin.test` last — prefer the 2-arg form); **`Uri.parse` returns null in
  plain JVM tests**.
